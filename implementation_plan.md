# Implementation Plan — Option B Backend-Driven Spin and Security Payouts

We will implement backend-driven spin selection and secure cryptographic verification. This will prevent users from faking winning outcomes (such as ₦200 Airtime or Super Flash Sale) in their browser and prevent over-allocation of limited prizes.

## Proposed Changes

### Backend Component (`server.js`)

#### [MODIFY] [server.js](file:///c:/Users/USER/Documents/Lush%20Spin%20the%20wheel%20300x250/server.js)
1. **Require Node.js Crypto Module**: Use `crypto` for SHA256 HMAC signature generation and verification.
2. **Schema Upgrade**:
   * Add a `prize_won` column to the `lush_claims` table structure on startup.
   * Verify it runs `ALTER TABLE lush_claims ADD COLUMN IF NOT EXISTS prize_won VARCHAR(100);` to preserve existing tables.
3. **Add `/api/spin` Endpoint**:
   * Use a **PostgreSQL Transaction-level Advisory Lock** (`SELECT pg_advisory_xact_lock(98765);`) to serialize concurrent draws.
   * Query the database to check if the `Super Flash Sale` count has already hit its limit of **2 wins**. If yes, set its weight to 0.
   * Run the weighted distribution selector:
     * *₦200 Airtime* (Weight 50)
     * *10% Discount* (Weight 50)
     * *Super Flash Sale* (Weight 0.02 or 0)
     * *Try Again* (Weight 30)
   * Generate an HMAC signature based on `{prize}:{page}:{timestamp}` using the `ADMIN_PASSWORD` as the secret key.
   * Return the result: `status, outcome, page, timestamp, signature`.
4. **Modify `/api/claim-prize` Handler**:
   * Extract `prize`, `timestamp`, and `signature` from the request.
   * Verify the cryptographic signature to ensure the prize was generated by the backend.
   * Enforce that the timestamp is less than 10 minutes old (prevent replay attacks).
   * Set `amount = 200` only if `prize === '₦200 Airtime'`. For other prizes (Discount/Flash Sale), save the claim details but set `amount = 0` and skip the airtime API payout.
   * Save the `prize_won` outcome to the database.

## Verification Plan

### Automated Tests
* Run `node server.js` to ensure the table schema updates.
* Use curl or Postman to test `/api/spin` and verify:
  * Weighted random distribution outputs are valid.
  * Signature is returned.
  * The second spin fails if same token is claimed twice.

### Manual Verification
* Test spinning the wheel in the browser.
* Verify the wheel lands on the correct sector matching the backend-selected outcome.
* Fill and submit the form to verify database entries and successful airtime triggers.
